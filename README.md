# 一起看（Together Watch）

这是一个多人在线观影同步工具。它不解析视频网站、不下载或代理第三方视频，也不读取任何人的 Cookie、账号或会员凭据。

每位成员都在视频网站的官方页面，用自己的账号和权限播放内容；房间服务器只传递播放、暂停、进度、倍速、缓冲状态、聊天与语音信令。这样启动更快、服务器流量更小，公开部署和后续商业化也更稳妥。

准备部署到公网时，请直接看 [DEPLOYMENT.md](DEPLOYMENT.md)。其中包含腾讯云境内低价年付服务器、ICP 备案、自动 HTTPS、部署后验收、TURN 配置和商业化升级清单。

## 能做什么

- 多人加入同一个房间，实时显示在线成员
- 同步播放、暂停、进度和倍速
- 某位成员持续缓冲时，全房间暂停；恢复后统一继续
- 房间文字聊天
- 多人 WebRTC 语音通话
- 识别哔哩哔哩、腾讯视频、爱奇艺、优酷、芒果 TV、抖音、快手、AcFun、YouTube 等官方页面
- 可选播放管理员预先登记的自有或已获授权媒体；任意 MP4/M3U8 直链默认拒绝

## 三分钟开始使用

### 1. 启动房间服务器

建议使用 Python 3.11 或更高版本：

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

打开 `http://localhost:5000`：

- 发起人输入昵称，点击“创建新房间”。
- 朋友打开邀请链接，输入自己的昵称，点击“加入已有房间”。
- 房间号会自动生成，不需要手动商量或输入。

### 2. 安装“观影伴侣”扩展

每位成员都需要安装一次：

1. Chrome 或 Edge 地址栏打开 `chrome://extensions` 或 `edge://extensions`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目的 `browser-extension` 文件夹。

也可以在房间里识别官方视频后，点击“下载观影伴侣”，解压安装包再加载文件夹。

扩展只监听官方页面中的 HTML5 播放器，并与房间服务器交换播放状态。它不会读取 Cookie，也不会获取或上传媒体地址。
保存配置时，浏览器会询问是否允许扩展连接你的房间服务器；这是建立同步 WebSocket 所必需的权限。

### 3. 一起看官方网页视频

扩展安装好以后，每次观影只需：

1. 在房间页粘贴官方视频网页地址。
2. 点击“使用这个链接”，确认来源后再点击“打开视频并在播放页聊天”。为避免抢走聊天室焦点，房间不会再自动跳转。
3. 官方播放页右侧会出现可收起的悬浮聊天室；聊天和播放同步都直接连接同一个房间。
4. 在各自的官方页面登录、选集并选择合适的画质。扩展会自动加入房间，角标显示“✓”后即可同步。

房间信息会跟随打开的视频页面自动带到扩展中，不需要再点击扩展或来回复制配置。只有自动识别失败时，才需要打开扩展检查状态，或展开“插件没有自动识别房间？”并使用手动配置。

会员内容由原网站校验，每位成员必须登录自己的账号并具备相应观看权限；本项目不会共享会员资格。管理员登记过的自有或已授权 MP4/M3U8 直链可以直接粘贴播放，不需要扩展。

大家必须打开同一集、同一版本。同步的是时间轴，不是视频画面；如果不同账号看到的是删减版、片头长度不同或广告时长不同，时间轴就无法天然对应。

### 4. 调整本机声音

房间页的“本机声音”中有两套独立滑块：

- “视频声音”只调整自己正在看的视频，不会改变其他人的音量。
- “通话声音”只调整自己听到的通话，不会影响麦克风发送给别人时的音量。

电脑端和大多数 Android 浏览器可直接使用两套滑块。iPhone/iPad 会限制网页和扩展修改媒体音量，因此视频声音请用机身音量键调整，通话声音仍可使用房间中的独立滑块。

### 5. 使用自有或已授权媒体（可选）

任意 MP4/M3U8 直链默认会被拒绝，不能由普通用户自行添加。只有管理员确认属于自有内容或已经取得足够授权后，才能把媒体域名写入 `AUTHORIZED_MEDIA_HOSTS`。登记后的媒体仍由源站直接发到每位成员的浏览器，本站不代理、不缓存。

不需要逐条登记视频。服务器上可以直接把一个域名或完整媒体链接交给管理脚本：

```bash
python3 scripts/manage_media_hosts.py --env-file .env.server add https://media.example.com/videos/movie.mp4 --confirm-rights
```

脚本只保存 `media.example.com`，不会保存这条视频地址。重新创建应用容器后，同一域名下的合规 MP4/M3U8 都可以直接粘贴：

```bash
sudo docker compose --env-file .env.server up -d --force-recreate app
```

查看或移除域名可使用 `list`、`remove media.example.com`。子域名不会被自动放行；确实需要时可明确登记 `*.media.example.com`。管理脚本会拒绝本机地址、IP 地址和已知官方视频平台，避免把官方会员媒体直链误当成授权来源。不要登记第三方影视站、临时签名域名或你无法持续证明授权的域名。

## 双方网速不同时怎样保证观感

“完全不缓冲”和“绝对同一帧”无法同时保证，但项目做了偏向观感的折中：

- 短暂网络抖动不会立刻拖停所有人，避免频繁一停一走。
- 成员持续缓冲超过约 1.2 秒才会上报；强一致模式会暂停全房间。
- 缓冲恢复后，服务器给出统一的未来恢复时间，成员一起继续。
- 小误差保持原速，大误差直接校准进度，避免反复变速造成声音变调。
- 官方页面的清晰度由每位成员独立选择。网络稍差的人可降清晰度，但仍共享同一时间轴。

若某位成员的网络长期无法跟上，建议他先降低官方播放器画质。强制让所有人等待最慢成员，会同步得更严，却会让整体观感更差。

## 语音通话

语音通话使用 WebRTC，媒体流在成员之间直接传输。麦克风在 `localhost` 或 HTTPS 页面可用。

公网部署建议配置 TURN，否则部分运营商网络、公司网络或严格 NAT 环境下可能无法建立通话。当前语音采用 Mesh，适合小型房间；人数明显增加后应迁移到 SFU。

## 本地与公网部署

Docker 镜像不再安装 Chrome、Chromedriver 或 FFmpeg，因此体积和启动开销都更小：

```bash
docker build -t together-watch .
docker run --rm -p 5000:5000 --env-file .env together-watch
```

面向中国大陆个人使用，推荐“备案后的境内低价年付轻量服务器 + Docker Compose + Caddy”。当前新用户活动档约 99 元/年；服务器只需安装 Docker，仓库中的 `compose.yaml` 会同时启动应用和 HTTPS 反向代理：

```bash
cp .env.server.example .env.server
nano .env.server
docker compose --env-file .env.server up -d --build
```

Caddy 会在域名解析生效后自动申请和续期 HTTPS 证书，并代理 WebSocket。完整购买、域名解析、防火墙和验收步骤见 [DEPLOYMENT.md](DEPLOYMENT.md)。

公开部署至少需要：

- HTTPS 域名
- 固定且足够长的 `SECRET_KEY`
- 与域名一致的 `ALLOWED_ORIGINS`
- 用于语音通话的 TURN
- 多实例部署时用于 Socket.IO 广播的 Redis

ngrok 只是一条临时公网隧道，不参与视频同步，也不会改善视频源速度。个人测试可以用它；长期面向中国大陆使用，优先选择备案后的境内轻量服务器，暂时不备案时再使用新加坡、日本或中国香港节点。

部署后可以用同一套脚本验证 HTTP、HTTPS/WSS、双客户端入房和播放同步：

```powershell
.\.venv\Scripts\python.exe scripts\smoke_test.py https://你的域名
```

## 环境变量

- `SECRET_KEY`：会话签名密钥，生产环境必须替换
- `PORT`：监听端口，默认 `5000`
- `ROOM_TTL_SECONDS`：空房间状态保留时间
- `MAX_ROOM_MEMBERS`：单房间最大在线人数，默认 50
- `MAX_CALL_MEMBERS`：单房间最大语音人数，默认 8
- `ALLOWED_ORIGINS`：允许连接 Socket.IO 的房间网页来源，多个地址用英文逗号分隔；观影伴侣的 Chromium 扩展来源会由服务端单独校验
- `WEBRTC_ICE_SERVERS`：WebRTC STUN/TURN 配置 JSON
- `SOCKETIO_MESSAGE_QUEUE`：多实例时使用的 Redis 等消息队列
- `AUTHORIZED_MEDIA_HOSTS`：允许直接播放的自有或已授权媒体域名；默认留空
- `AUTHORIZED_PAGE_HOSTS`：内置官方平台以外，经审核允许同步的自有网页域名；默认留空
- `SERVICE_OPERATOR_NAME`：公开展示的真实运营者姓名或公司名称；生产环境必填
- `COPYRIGHT_CONTACT_EMAIL`：用户协议、隐私政策和版权投诉页面显示的联系邮箱

旧上传、网页解析、视频代理和转码链路已经在代码中永久关闭，不再提供可重新开启的环境变量。

## 边界与合规

- 本项目不会绕过 DRM、会员权限、验证码、防盗链或地域限制。
- 房主分享的是房间和播放状态，不是视频文件或会员账号。
- 每位成员都应通过合法渠道获取内容访问权。
- 项目已提供用户协议、隐私政策和版权投诉入口；生产环境必须配置 `SERVICE_OPERATOR_NAME` 和真实可用的 `COPYRIGHT_CONTACT_EMAIL`，否则不能添加视频来源。上线后仍需安排人工处理投诉并移除授权失效的域名。
- 上述技术措施不能替代针对实际业务、内容来源和经营地区的专业法律审查；商用前仍需处理备案、广告、未成年人保护和数据合规事项。

## 常见问题

**为什么以前会显示“不允许访问本机、局域网或保留地址”？**  
那是旧服务器解析/代理链路为防止 SSRF 做的限制。新模式不再让服务器访问粘贴的网址，官方页面只在用户自己的浏览器中打开。

**为什么“识别来源”现在很快？**  
它只做 URL 格式和站点识别，不请求源网站，也不启动浏览器解析器。

**为什么官方页面没有跟着同步？**  
确认每位成员都安装了扩展、保存了同一服务器和房间配置、刷新了官方页面，并且扩展角标显示“✓”。

**为什么还是会错位？**  
先确认所有人打开同一集和同一版本，并跳过各自不同长度的广告。部分站点会把片头、广告插在不同时间线中，这类差异无法只靠秒数自动判断。
