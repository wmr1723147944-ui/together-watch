# 一起看 Windows 测试版 0.6.3

## 先选影片，再建房间（0.6.3）

启动直接进入推荐封面与搜索页，不再先展示来源清单或要求填写房间表单。搜索结果统一显示影片，同名且年份一致的结果合并；打开影片后才选择来源和集数，确认昵称及使用说明后建房。“加入房间”仍可只填邀请或房间号，不用重复选片。

此版保留 0.6.2 的房间号与安卓房主互通修复，配套安卓 0.3.3。已完成本地打包与测试，代码推送不会自动部署服务器。**首页必须同时更新服务器才会变化**。两个安装包、服务器命令与手机建房验收步骤见 [新版首页与完整更新步骤](../FILM_HOME_2026-10-21.md)。

## 房间号与安卓房主互通（0.6.2）

支持纯房间号、带房间号标签的复制文本、网页查询参数邀请及分享文案；点击顶部房间号可以复制。配套安卓 0.3.2 修复“填了房间号却另开房”和兼容房间同步路径。两个包、服务器发布状态与完整测试步骤见 [进房与同步修复说明](../ROOM_JOIN_SYNC_2026-10-21.md)。

## 搜索封面与影院布局（0.6.1）

找片页与首页搜索区采用深色背景、海报卡片和手机双列布局。封面来自结果所属来源的公开图片元数据，不通过片名另配图片；加载失败仍可选集。Windows 的看剧 AI、233 动漫、七味网本机目录读取现在保留通过校验的封面地址。

需要同时更新服务器到 `20261021-poster-catalog`，只更换 EXE 不会改变服务器页面。旧 Windows 可以显示新版服务端来源的封面，但本机目录封面需 0.6.1。更新步骤见仓库根目录 `SEARCH_POSTERS_2026-10-21.md`。以下保留历史说明。

## 看剧 AI 目录与选集（0.6.0）

“找片”中可勾选“看剧 AI · Windows”，由本机正常打开原站目录、读取已展示片名和集数，再选集建房和邀请同集。不调用或代签原站私有接口。原站未确认所选集数时不开始同步；部分集数尚未加载会明确标注。需配套更新服务器，旧客户端和网页保留原站入口。

本地模拟三站双端流程已通过，真实看剧 AI 正片尚未完成验收，不能保证所有影片可播。详细范围与测试方式见 `KANJU_CATALOG_2026-10-19.md`。以下章节保留历史版本说明。

## 少走回头路（0.5.2）

在“搜片 / 网站目录”和最近打开的一个原站之间切换，不再关闭重开页面：搜索输入、结果、当前原站页面及未完成表单留在当前窗口内存中。再次点击同一站点可回到刚才的位置，不自动点击登录或验证码。

为避免占用越来越多内存，只保留找片页和最近一个原站。打开另一个站点、建房、返回首页或退出软件会关闭相应页面，原站允许保存的本机登录状态仍由浏览器会话保留。隐藏页面会静音并尝试暂停音视频，恢复后按需点播放；不会将表单或登录状态写入房间、邀请或服务器。原站自己的刷新、跳转、验证过期仍可能要求重试。

## 精简目录（r3）

按用户要求，从本批推荐中移除 10 个入口：ZRF 聚合直播、星火直播、OmoFun、爱迪影视、努努剧、Plex、Pluto、Tubi、Xumo、Vudu；Plex / Tubi 的重复导航一并移除。当前保留 9 个目录入口，服务器 `/api/discover/sites` 版本为 `20261019-site-directory-r3`。移除记录保存在项目中，可恢复，不宣称这些站点永久失效。

登录 / 验证类仍保留。Windows 原站浏览使用本机持久会话，在软件内完成登录 / 验证后，可沿用原站允许保存的状态，不必为了每次换片主动清空状态。原站可能因过期、网络变化等重新要求验证，不能承诺永久免验证。每个人使用自己的状态，不向房间或其他成员共享。

已适配的 233 动漫、七味网可在实际需要时弹出原站验证窗口，完成后接回统一搜索 / 选集。ZRF 影视、风铃、Noxx、OnDemandChina、优视频目前仍为原站浏览入口，尚无统一搜索自动接回适配；403 拒绝访问也不一定能通过验证解决。

客户端目录数据同样已精简，需换成 0.5.1 或更新版才同步移除内置站点识别；0.5.2 额外保留找片上下文。只部署服务器会先隐藏页面入口，不会替换旧 EXE。当前修改不等于已发布或已部署。

## 目录站点逐站适配（2026-10-19）

这一批将 **233 动漫、七味网** 从“原站入口”提升为统一搜索、详情、线路 / 选集和邀请同集。其他 17 个目录入口仍未完整适配，不代表都能播放。逐站障碍和验收范围见根目录 `CATALOG_INTEGRATION_2026-10-19.md`。

1. 更新服务器，并将双方 Windows 客户端换为 0.5.0。服务端 `/api/discover/sources` 版本应为 `20261019-catalog-adapters`，来源中应包含 `233dm`、`pkavi`。未启用这些来源时，客户端不会自行开启它们。
2. 先找片，勾选来源后搜索片名。两站在 Windows 中使用本机隔离网页读取公开目录；验证状态留在本机，账号、Cookie、视频流不会随邀请发给别人。
3. 原站可以直接查询时，不弹验证窗口。只有实际返回验证页才显示“在软件中验证并继续搜索”，由你自行完成；结果返回同一个搜索页，无需重输片名。详情页也支持验证后继续读取集数。
4. 选好具体线路和集数再建房。朋友只填邀请链接，自动打开同一来源、条目和集数；各自仍需满足原站观看条件，浏览器要求用户手势时需点一次播放。房主换集后成员跟随。
5. 清空、换条件、关闭详情或离开找片页，会取消对应待处理查询。验证窗口也可以直接关闭。失败时保留原站入口，不把失败结果当成“没这部片”。

这次已验证真实公开详情 HTML 的提取与本地模拟双客户端全流程；**尚未通过两站正片实播验收**。搜索请求在本次网络遇到原站验证，不替用户解验证码，不承诺所有影片、画质或地区可用。浏览器和安卓没有这次 Windows 的本机验证桥接，不能把服务器搜索等同于客户端完整流程。

本地回归可用 `TW_SMOKE_CATALOG_ONLY=1`；模拟验证码只在测试夹具里手动触发，不操作真实验证码。`TW_CATALOG_SAMPLES` 可指定离线公开 HTML 样本清单，核对 DOM 解析与服务器解析的一致性，样本不会打包进软件。

## 帖子站点目录（2026-10-19）

以下记录 0.4.1 的初始目录范围；当前新增的两站能力以上一节为准。

“找片 / 网站目录”中新增 **更多网站 · 原站内搜索**，可按站名、类型和访问状态筛选。核对了帖子里的 39 个独立地址，保留 19 个原站入口（其中 Tubi / Plex 已在官方导航中出现），20 个未确认或失效地址不提供打开按钮。详细名单和原因见根目录 `SITE_DIRECTORY_2026-10-19.md` 与 `static/data/site-directory.json`。

- 点击入口在隔离的原站网页中浏览，不会立刻创建房间。验证、登录由用户自己操作；软件不自动解验证码，也不读取、导出或分享凭据。
- 支持后退、刷新重试、在系统浏览器打开。跨站新窗口先询问；未知域名的自动重定向会暂停，不自动登记为可信片源。发布页可手动确认新地址，但它不会加入服务器自动搜索。

- 这 19 个入口**没有加入自动聚合搜片**。原有 6 个查询来源及已适配邀请流程保持不变；目录不意味着正片实播、授权、免费或 4K 已核实。地区限制与访问拦截仍可能导致无法使用。
- 需同时更新服务器（`/api/discover/sites` 返回 `20261019-site-directory`）与客户端。旧版网页或 EXE 不会自动获得所有新操作。

`TW_SMOKE_DIRECTORY_ONLY=1` 用本地模拟验证页检查原站隔离、等待手动操作、刷新、导航、确认兼容建房、播放器连接与桌面/手机布局，不将模拟测试称为真实验证码通过或第三方正片测试。

## 先选片，再邀请（2026-10-19）

本节是当前操作方式，下方 0.3 历史说明仅解释播放器能力。

1. 首页输入昵称、勾选使用说明，房间和视频地址都留空，点击“先找片，选好再建房”。此时没有创建房间。
2. 搜索片名 → 详情 / 选集 → 点击具体集数，才创建带有片源记录的房间。
3. 房主点“复制邀请”。朋友在 **Windows 0.4.0** 首页只填昵称、邀请链接并同意说明，视频地址不用填；加载后自动追赶房间进度。浏览器要求用户手势时仍需点一次播放，不会关闭自动播放保护。
4. 房主从“找片 / 选集”切换集数，其他新版客户端自动跟随。成员仍可正常暂停、拖动进度；只有房主能替换房间片源。
5. “看剧 AI”使用已核实的 `https://www.kanju.ai/` 原站入口，可在软件内搜索、登录并进入播放页。打开 `/player/…` 后点“用当前播放页建房 / 换片”。**尚未接入其会话 API 自动聚合搜索，也未验证其影片实播或版权。**

看剧 AI 和 DDYS 目前仅记录原站页面，无法保证精确到动态集数；双方须核对同一集，再点“重连同步”。其他有固定集数标识的目录才会自动选集。自填任意媒体地址仍走兼容房间，不会把签名、Cookie 或视频流转发给朋友。

**0.4.0 必须同时更新服务器和 Windows 压缩包。** 服务端 `/api/discover/sources` 版本应为 `20261018-watch-rooms`。旧 EXE、安卓 APP 和普通网页尚未实现本次邀请自动选集，不能把本机测试结果当作跨端均已支持。

房间记录沿用服务端内存存储和空房过期策略；服务器重启会清空。房主权限只保存在当前 Windows 窗口的主进程中，返回首页再入房可保留，完全退出软件后需要重新选片建房，不能从普通邀请恢复房主权限。请仅向受邀朋友发送链接。

`TW_SMOKE_INVITE_ONLY=1` 验证搜索未建房、选集建房、邀请无视频地址入房、晚加入追赶、暂停 / 拖动、换片隔离、访客不能改片以及失效邀请。`TW_SMOKE_KANJU_LIVE=1` 额外只读检查原站首页，不代表通过正片播放测试。

## 独立内置播放（2026-10-17）

这一版新增“网页识别 → 选择候选 → 独立播放器”的流程，参考 Kazumi 的职责拆分，独立实现，不复制其 GPL 代码或捆绑社区片源规则。播放器仍是 Chromium + HLS.js，**不是 mpv / Media3 原生解码器，也不保证所有站点可播**。

1. 创建或加入房间，在“找片 / 选集”打开想看的播放页，先用网页开始播放。
2. 点“识别视频”，在候选框选中对应的媒体，再点“内置播放”。候选标注格式、域名、文件名；网页能读到时长时也显示时长。短视频可能是广告，需要自己核对。
3. 内置播放器加载完成后点播放。在同一窗口内暂停、拖进度、改倍速，右侧房间保持连接；另一位成员仍需自行打开同一集、同一版本。
4. HLS 有多档画质时可选实际提供的分辨率。不会把普通片源标为 4K。F11 全屏，Esc 返回；“铺满 / 完整”选择裁边或保留完整画面。
5. 加载失败会给出提示，点“原网页”退回原页面；返回后按需手动播放。不会替你绕过源站登录、付费、DRM、跨域或防盗链。

支持公开 HTTPS MP4 / M4V / WebM 和允许跨域的 HLS；不支持直接搬运 blob、DASH、受保护媒体。网络 MIME 识别也可发现无扩展名的 MP4 / HLS。识别过程仅观察当前页面已发出的请求及视频元素，不扫描外部网站。最多保留当前页 24 项，导航会作废旧候选；不自动选广告、不自动抓取下一集。

媒体地址只留在本机，不进房间消息或服务端。独立播放器使用不持久化的隔离会话，不带原站 Cookie / Authorization，不篡改源站响应头、关闭网页安全策略或代理视频。原网页在内置播放期间静音并暂停，保留作为回退入口。

历史 0.3.0 仅需换客户端；当前 0.4.0 还需更新上文的服务器选片协议。

## 软件内找片与选集（2026-10-17）

先确认 `/api/discover/sources` 的版本为 `20261017-ddys-ui`，再换用新版客户端；只更新网站不会给旧 EXE 增加客户端按钮。

- 视频链接可留空，创建 / 加入房间后直接打开找片页。已进入房间可点“找片 / 选集”。
- 搜索后点“详情 / 选集”，再点击具体集数。识别到视频后在影院模式中显示视频和控制条，聊天室保留。
- “回到播放”返回当前视频；“找片 / 选集”保留上一轮结果和详情，不退出房间。“影院 / 网页”恢复原站界面，便于登录、选择原站线路。
- 茶杯狐 `www.cupfox.in` 读取公开 `ep_slug` 集数，仅由本机点击原站的选集按钮；服务器不请求其视频接口。Blender 使用官方频道目录。华人影院目前本地连接失败，不能承诺可选集或播放。
- 新增樱花 `yhdmoe.com`、风车 `www.fcma.cc` 的目录搜索和公开选集；长列表可按集数 / 线路筛选，每批显示 100 个。这里仅确认目录与跳转规则，不保证第三方影片实播、版权或 4K。爱壹帆受到访问限制、影视岛未核实到可靠地址，未加入自动搜索。
- 没确认选中集数时停止自动接入同步，提示回网页操作，不默认把其他集数当作成功。
- 原网页模式仍用隔离的 Chromium 播放原网页；0.3 另外提供上文的独立内置播放。没有破解 DRM、复制 Cookie、视频代理或去广告承诺；原站是否可播、是否有权观看需各自确认。
- 安卓和普通浏览器这次只获得新版搜索 / 详情界面，尚未接入新选集跳转，应使用“改用原站选集”。

这是独立桌面客户端，不需要书签、浏览器扩展、Python 或 Node。左侧保留视频来源网页，右侧是一起看房间。它不是把第三方影片转发到服务器，也不是支持所有资源的万能播放器。

## 怎么打开

1. 将 Windows 压缩包**完整解压**到一个文件夹。
2. 双击 `TogetherWatch.exe`。不要只把 EXE 单独拷走，它需要同文件夹中的运行库和 `resources`。
3. 输入昵称，先点 `Sintel` 或 `Big Buck Bunny` 选择公开短片，勾选使用说明后开始。
4. 点“复制邀请”，把链接发给朋友。0.4.0 朋友只填写邀请；公开示例片或已识别集数的片源由服务器记录带出，不需要再选短片。
5. 播放、暂停、拖进度及倍速在左侧视频中操作，右侧直接聊天。必要时先在网页点一次播放。

`F11` 进入全屏，`Esc` / `F11` 返回；全屏下 `Ctrl+Z` 切换完整画面与铺满裁边。默认不拉伸、也不裁掉影片。原影片自带黑边不会凭空消失。

目前提供 Windows x64 便携测试包，未做代码签名、安装器和自动更新。系统可能提示未知发布者；不要关闭系统安全防护，只运行你确认来自本项目的包。关闭主窗口会退出房间。

## 上线前先更新服务器

本次修复了 `mobile-room.js` 向 Socket.IO 传入空回调导致多一个消息参数的问题。旧服务器可能显示“已连接”却收不到播放事件。**仅安装客户端不会修复旧服务器。**

代码推送后，在 Ubuntu 服务器的项目目录执行，确认每一步成功后再继续：

```bash
cd ~/together-watch
git pull --ff-only
sudo docker compose --env-file .env.server up -d --build app
sudo docker compose --env-file .env.server ps
```

不用在 Windows PowerShell 执行这组服务器命令，也不用改 `.env.server`。更新后双方退出房间重新进入。

## 当前边界

- 自动识别普通 HTML5 视频、可访问的嵌套页面和开放 Shadow DOM。部分广告、多播放器、封闭组件、定制控制条可能需要“重新识别播放器”，不能保证任意网站兼容。
- 这是 Chromium + HLS.js 播放器，不是 Android Media3 的 Windows 移植版。使用本站搜片和有限来源的手动选集；不导入任意资源规则，不自动下一集，不提供下载或任意 DASH 解析。
- 固定集数来源可按邀请自动打开；动态选集或兼容房间仍需自行核对同一集、同一版本，并用自己的观看权限登录。付费、DRM、验证码、禁止嵌入浏览器或特殊登录弹窗可能不兼容，不破解限制。
- 房间协议包含受限的来源 / 条目 / 集数标识及播放状态；服务器重建固定公开播放页。内置播放识别的媒体地址仅在本机使用，不转发给其他成员。原网页登录 Cookie 由本机 Chromium 保存，与房间和独立播放器隔离；应用不复制这些凭据。页面自身仍会正常联网。
- 输入入口拒绝 HTTP、IP、凭据 URL 和本地域名。这是导航限制，不是 DNS 或全系统网络隔离；不要把未知网页当成可信内容。
- 第三方视频页不能使用应用的 Node/文件接口，也不能申请麦克风。只有本站房间在你确认后可申请语音麦克风。
- 语音保留现有 WebRTC 功能，本轮未做真实麦克风、跨运营商网络测试。服务器缺少 TURN 时，严格 NAT 下仍可能无声或连接失败。
- 测试版不自动更新内置浏览器，后续需要手动换新包。不要长期使用过时版本。

## 开发与验证

Node 22.12+，Electron 44.7.0，依赖锁定在 `package-lock.json`：

```powershell
cd desktop-app
npm ci
npm test
npm start
npm run package:win
```

输出 `dist/TogetherWatch-win32-x64/`。运行时不需要开发依赖。保留发行目录中的 Electron/Chromium 第三方许可文件。

集成测试会创建隐藏 Electron 窗口，启动仅监听 `127.0.0.1` 的临时 Flask 服务，不操作公网房间。先安装根目录的 Python 依赖，并将一个可拖进度的测试 MP4 放在 `.review-artifacts/desktop-smoke/sintel.mp4`，或指定 `TW_SMOKE_MEDIA`；可用 `TW_SMOKE_PYTHON` 指定 Python 路径，再运行 `npm run smoke`。

测试范围包括真实跨源 iframe 播放器、双向暂停/进度/倍速、音量隔离、聊天、全屏尺寸及退出清理。它不能代替真机声音、第三方站点兼容性和不同网络条件下的验收。

`TW_SMOKE_BUILTIN_ONLY=1` 单独运行内置播放的双客户端集成测试（实际解码本地 MP4，验证双向操作、回退、候选失效及 403 提示）。再设置 `TW_SMOKE_LIVE_MEDIA=1` 可增加公开 W3C MP4 和 HLS.js 演示流的真实网络实播检查。网络测试只在测试会话中使用直连，不修改用户或系统代理。HLS.js 复用网站现有的 1.5.18 vendored 文件；`prepackage:win` 复制到发行包，保留 `HLS-NOTICE.txt` 与 `HLS-APACHE-2.0.txt`。

随后还会验证“手机宽度的普通房间网页 + Windows 客户端”：双向控制、定期状态刷新、模拟浏览器拒绝自动播放，以及点击按钮后只恢复本机播放。设 `TW_SMOKE_MIXED_ONLY=1` 可单独运行这部分。手机窗口使用桌面 Chromium，不代表已经覆盖安卓或 iOS 真机；自动播放拒绝由测试注入，未关闭浏览器安全策略。测试媒体路由和房间初始化仅存在于开发测试服务中，不加入生产服务器。
